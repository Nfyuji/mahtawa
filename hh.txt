# المهمة: بناء محرك ذكاء اصطناعي لاكتشاف الاتجاهات وتحليل السوق وإنتاج محتوى اجتماعي

أريد تطوير منصة SaaS احترافية متعددة العملاء، مستوحاة من قدرات أدوات اكتشاف الاتجاهات والاستماع الاجتماعي وإنتاج المحتوى مثل Hootsuite وPredis.ai، مع بناء نظام مستقل يعتمد على مصادر البيانات الرسمية وواجهات API الموثقة.

**الهدف ليس تقليد واجهة هذه المنصات، بل بناء نظام فعلي يجمع البيانات، ويحللها، ويكتشف الفرص، ويحوّلها إلى محتوى تسويقي قابل للقياس.**

## أولًا: قواعد إلزامية قبل البرمجة

1. افحص المشروع الحالي ومجلداته والتقنيات وقاعدة البيانات قبل تعديل أي شيء.
2. استخدم الوثائق الرسمية وحدها لتحديد قدرات كل API وطريقة المصادقة والحدود والتكلفة وشروط الاستخدام.
3. لا تفترض أن كل بيانات مواقع التواصل متاحة للعامة أو عبر API.
4. لا تستخدم Scraping مخالفًا لشروط المواقع، ولا تتجاوز المصادقة أو القيود أو حدود الطلبات.
5. لا تخترع نقاط API أو أسماء الحقول أو استجابات غير موثقة.
6. إذا كانت الميزة غير متاحة رسميًا، وضّح ذلك واقترح بديلًا قانونيًا، مثل رفع ملف يدويًا أو استخدام مصدر بيانات بديل.
7. لا تضع مفاتيح API داخل الواجهة الأمامية أو المستودع البرمجي؛ استخدم متغيرات البيئة وإدارة أسرار آمنة.
8. لا تنتقل إلى التكامل التالي قبل توثيق التكامل الحالي واختباره.

أنشئ ملفًا باسم `docs/integrations-research.md` يتضمن لكل مصدر:

* الوظائف المتاحة رسميًا.
* رابط الوثائق التي تثبت كل وظيفة.
* نوع المصادقة المطلوبة.
* البيانات التي يمكن الحصول عليها.
* القيود وحدود الطلبات والتكلفة إن كانت موثقة.
* ما لا يمكن الوصول إليه.
* خطوات الإعداد والاختبار.
* حالة التكامل: متحقق، يحتاج بيانات اعتماد، أو غير متاح.

## ثالثًا: بناء نظام جمع البيانات

أنشئ وحدة مستقلة باسم `Trend Discovery Engine`.

مسؤولياتها:

1. استقبال طلب بحث يتضمن المجال، والكلمات المفتاحية، والبلد، واللغة، والفترة الزمنية.
2. تحديد مصادر البيانات المناسبة لكل طلب.
3. جلب البيانات من المصادر الرسمية المتاحة باستخدام موصل مستقل لكل مصدر.
4. توحيد البيانات في نموذج داخلي موحد.
5. حفظ المصدر الأصلي، ورابطه عند توفره، ووقت جمع البيانات، ووقت آخر تحديث.
6. حفظ اللقطات الزمنية اللازمة لمقارنة تغير المؤشرات عبر الأيام والأسابيع.
7. إزالة التكرار، ومعالجة الأخطاء، وتطبيق حدود الطلبات.
8. تخزين النتائج مؤقتًا لتجنب استهلاك API بلا داعٍ.
9. تسجيل حالات النجاح والفشل وسبب كل فشل.

لا تعتمد على مصدر واحد لكل أنواع الاتجاهات. افصل بين:

* اتجاهات البحث.
* اتجاهات الهاشتاقات.
* أداء محتوى حساب العميل.
* معلومات المنافسين المتاحة رسميًا.
* الأخبار والمقالات والمصادر العامة الموثوقة.

إذا لم يتوفر تكامل آلي لمصدر ما، أنشئ واجهة واضحة لرفع البيانات أو إدخال رابط المصدر يدويًا، ولا تعرض بيانات وهمية على أنها بيانات حقيقية.

## رابعًا: بناء محرك اكتشاف الاتجاهات

أنشئ خدمة تحليل تستقبل البيانات المجمعة وتنتج قائمة بالموضوعات والفرص التسويقية.

لكل موضوع، احسب أو استخرج عند توفر البيانات:

* اسم الموضوع والكلمات المرتبطة به.
* السوق واللغة والفترة الزمنية.
* المؤشر الحالي والمؤشرات السابقة.
* مقدار التغير واتجاهه.
* حداثة البيانات.
* صلة الموضوع بنشاط العميل.
* مستوى موثوقية المصدر.
* الأدلة التي تدعم الاستنتاج.
* تاريخ آخر تحديث.

لا تقارن مقاييس غير متكافئة بين المنصات. ميّز بين حجم البحث، وعدد المنشورات، والمشاهدات، ومؤشرات الاهتمام النسبية.

أنشئ درجة لترتيب الفرص، مع توثيق معادلتها وأوزانها وإمكانية تعديلها. إذا لم تتوفر بيانات كافية لحساب النمو، أظهر أن النمو غير معروف بدل اختلاق قيمة.

صنّف النتائج إلى:

* اتجاه متصاعد تدعمه البيانات.
* موضوع مستمر.
* موضوع موسمي.
* إشارة تحتاج إلى مزيد من التحقق.
* موضوع غير ملائم لنشاط العميل.

لا تدّعِ أن النظام يتنبأ بالانتشار بصورة مؤكدة.

## خامسًا: بناء محلل السوق والمنافسين

أنشئ وحدة تسمح للعميل بإضافة:

* اسم العلامة التجارية.
* وصف النشاط والمنتجات والخدمات.
* البلد والجمهور المستهدف.
* حساباته الاجتماعية.
* روابط المنافسين ومواقعهم.
* الأهداف التسويقية.

حلّل فقط البيانات التي يستطيع النظام الوصول إليها قانونيًا ورسميًا.

استخدم نموذج ذكاء اصطناعي لتصنيف المحتوى إلى:

* تثقيفي.
* ترفيهي.
* ترويجي.
* قصص وتجارب عملاء.
* أسئلة ومشكلات الجمهور.
* عروض ومقارنات.
* أنواع أخرى يحددها النظام.

استخرج الموضوعات المتكررة، والأسئلة، ونقاط الألم، وأنواع المحتوى التي تستحق الاختبار.

افصل بوضوح بين:

1. البيانات المرصودة مباشرة.
2. النتائج الحسابية المستخرجة من البيانات.
3. تفسيرات الذكاء الاصطناعي.
4. الفرضيات التي تحتاج إلى اختبار.

لا تستنتج مبيعات المنافسين أو معدل تحويلهم أو بياناتهم الخاصة ما لم تتوفر بيانات موثوقة تثبت ذلك.

## سادسًا: بناء محرك إنتاج المحتوى

أنشئ وحدة مستقلة باسم `AI Content Studio`.

تستقبل الوحدة:

* ملف العلامة التجارية.
* الجمهور المستهدف.
* أهداف التسويق.
* نتائج بحث السوق.
* الاتجاهات المؤكدة والموضوعات المقترحة.
* بيانات أداء محتوى العميل السابق.
* منصة النشر المطلوبة.
* نوع المحتوى واللغة والنبرة.

ثم تنتج:

1. الفكرة التسويقية.
2. سبب اختيار الفكرة والأدلة المرتبطة بها.
3. الخطاف الافتتاحي.
4. سيناريو الفيديو وتقسيم المشاهد.
5. النص الظاهر على الشاشة.
6. التعليق الصوتي عند الحاجة.
7. وصف المنشور.
8. الدعوة إلى الإجراء.
9. الهاشتاقات المقترحة.
10. تعليمات التصميم والوسائط.
11. نسخًا معدلة لكل منصة.
12. مؤشرات نجاح مستهدفة للاختبار، دون ضمان نتائج مستقبلية.

استخدم OpenAI API لتوليد المحتوى وتحليل البيانات، مع مخرجات Structured Outputs وفق مخطط بيانات محدد، والتحقق من صحة النتائج قبل حفظها.

لا تطلب من نموذج اللغة اختلاق اتجاهات أو إحصاءات أو مصادر. مرر له الأدلة المجمعة، واطلب منه ربط كل ادعاء بمصدره أو تصنيفه على أنه اقتراح غير مثبت.

## سابعًا: التكامل مع Predis.ai

أنشئ موصلًا مستقلًا باسم `PredisConnector` باستخدام الوثائق الرسمية الحالية فقط.

يجب أن يدعم، عند توفر الصلاحيات:

* التحقق من إعدادات التكامل.
* تخزين مفتاح API بصورة آمنة.
* اختيار العلامة التجارية ومعرّفها.
* إرسال موضوع المحتوى إلى واجهة إنشاء المحتوى الرسمية.
* تحديد نوع المحتوى والخيارات التي تدعمها الوثائق.
* حفظ معرّفات المهام والنتائج.
* استقبال Webhooks لتحديث حالات إنشاء المحتوى.
* التعامل مع حالات قيد التنفيذ والنجاح والفشل.
* إعادة المحاولة بأمان عند الأخطاء المؤقتة، ومنع تكرار إنشاء المحتوى دون داعٍ.
* تسجيل الاستهلاك والتكلفة عند توفر بيانات موثوقة عنها.

تحقق من أسعار API وشروطها وحدود الاستخدام قبل تفعيل التكامل للعملاء.

لا تفترض أن Predis.ai يوفر اكتشاف الاتجاهات أو النشر المباشر لكل منصة ضمن نفس API؛ افصل إنشاء المحتوى عن اكتشاف الاتجاهات وعن النشر.

إذا لم تتوفر بيانات اعتماد Predis.ai، أنشئ واجهة الموصل والاختبارات باستخدام بيانات وهمية في بيئة الاختبار فقط، مع وضع علامة واضحة على البيانات التجريبية.

## ثامنًا: حلقة التعلم والتحسين

أنشئ وحدة باسم `Content Performance Learning`.

اجمع أداء المنشورات الخاصة بالعميل من واجهات المنصات الرسمية عندما تسمح بذلك، مثل:

* المشاهدات أو مرات الظهور.
* التفاعل.
* النقرات.
* الاحتفاظ بالمشاهدين إذا كانت البيانات متاحة.
* التحويلات عند وجود تكامل موثوق.
* وقت النشر ونوع المحتوى وموضوعه.

قارن أداء المنشورات بحسب الهدف، ولا تعتمد على المشاهدات وحدها.

اربط كل نتيجة بخصائص المحتوى الذي أنتجها. أنشئ تقارير توضّح:

* ما الذي نجح وفق البيانات المتاحة؟
* ما الذي لم ينجح؟
* ما الذي لا تزال الأدلة بشأنه غير كافية؟
* ما التجربة التالية التي ينبغي اختبارها؟
* كيف نقيس نجاح التجربة الجديدة؟

لا تدّعِ السببية اعتمادًا على الارتباط وحده. استخدم اختبارات مقارنة مناسبة عندما تسمح الظروف بذلك، وسجّل حجم العينة والقيود.

## تاسعًا: المعمارية والتقنيات

افحص التقنيات الموجودة أولًا. إذا كان المشروع جديدًا، فاعتمد بنية قابلة للتوسع دون تقسيم مبكر إلى خدمات كثيرة:

* Laravel + PHP لإدارة الحسابات والاشتراكات والصلاحيات وواجهات النظام.
* PostgreSQL لحفظ بيانات العملاء والاتجاهات والمحتوى والنتائج.
* Redis وطوابير المهام للعمليات الطويلة وإعادة المحاولة.
* Python + FastAPI عند الحاجة إلى خدمة تحليل مستقلة.
* OpenAI API لمعالجة اللغة والتلخيص والتصنيف وتوليد المحتوى.
* تخزين متوافق مع S3 للصور والملفات الناتجة.
* واجهة ويب عربية RTL تدعم الإنجليزية LTR عند الحاجة.

اجعل كل عميل معزولًا عن بيانات العملاء الآخرين. طبّق الصلاحيات، والتشفير، والتحقق من Webhooks، ومعدلات الطلبات، وسجل التدقيق.

لا تبدأ باستخدام Kubernetes أو بنية Microservices معقدة دون حاجة مثبتة.

المرحلة الأولى:

* فحص المشروع.
* مراجعة الوثائق الرسمية.
* إعداد مخطط المعمارية وقاعدة البيانات.
* توثيق حدود كل تكامل.

المرحلة الثانية:

المرحلة الثالثة:

4. ما يعمل فعليًا وما يحتاج إلى بيانات اعتماد.

...............................................### محرك جذب الانتباه وكتابة Hooks الذكية

أنشئ Hook Engine متكاملًا داخل محرك توليد المحتوى، بحيث يكون لكل منشور أو فيديو افتتاحية مصممة لجذب الجمهور المستهدف وتشجيعه على مواصلة المشاهدة أو القراءة.

**1. البحث قبل الكتابة**

* تحليل الجمهور المستهدف ومشكلاته وأسئلته ورغباته.
* الاستفادة من الاتجاهات الحديثة والمنافسين ونتائج المحتوى السابق عند توفر بيانات موثوقة.
* عدم اختلاق إحصائيات أو ادعاء أن Hook ناجح دون دليل.

**2. توليد عدة افتتاحيات**
لكل فكرة محتوى، أنشئ 5 Hooks مختلفة على الأقل، باستخدام أساليب متنوعة:

* الفضول والتشويق.
* المشكلة والألم.
* الفائدة والنتيجة.
* السؤال المباشر.
* كسر المعتقدات.
* الخطأ الشائع.
* القصة والتجربة.
* المقارنة والمفاجأة.
* التحدي أو الاختبار.
* الدليل أو النتيجة الموثقة.

**3. اختيار أفضل Hook**
قيّم كل افتتاحية وفقًا إلى:

* ارتباطها باهتمامات الجمهور.
* وضوحها وسهولة فهمها.
* قوة الفضول الذي تثيره.
* ارتباطها بهدف المحتوى.
* ملاءمتها للمنصة ونوع المحتوى.
* مصداقيتها وعدم تضليل الجمهور.
* اختلافها عن الافتتاحيات المستخدمة مؤخرًا.

اعرض التقييم باعتباره تقديرًا داخليًا للمفاضلة، وليس توقعًا مضمونًا للمشاهدات أو الانتشار.

**4. ربط Hook ببقية المحتوى**

* يجب أن يفي المحتوى بالوعد الذي تقدمه الافتتاحية.
* في الفيديو، اكتب الافتتاحية المنطوقة والنص الظاهر على الشاشة.
* في المنشورات النصية، اجعل السطر الأول جذابًا وواضحًا.
* في الكاروسيل، اجعل الشريحة الأولى مشوقة وتوضح سبب متابعة الشرائح التالية.
* تجنب المقدمات الطويلة والتحيات العامة قبل الوصول إلى الفكرة.
* أضف انتقالًا منطقيًا من الافتتاحية إلى القيمة الأساسية ثم دعوة مناسبة لاتخاذ إجراء.

**5. اختبارات A/B**
أنشئ نسختين أو ثلاثًا من Hook للفكرة نفسها، مع إبقاء بقية المحتوى متقاربة عند الاختبار. قارن النتائج باستخدام البيانات الفعلية المتاحة، مثل الاحتفاظ بالمشاهدة والتفاعل والنقرات والتحويلات. لا تعلن عن فائز دون بيانات كافية.

**6. التخصيص والتنوع**
خصص أسلوب الافتتاحية حسب مجال العميل والجمهور والمنصة ومرحلة رحلة العميل. امنع تكرار الصياغات والقوالب بشكل ملحوظ عبر خطة المحتوى الشهرية، مع الحفاظ على صوت العلامة التجارية.

**7. واجهة الاستخدام**
اعرض Hooks البديلة بجانب كل فكرة، مع أزرار لاختيار افتتاحية أو تعديلها أو إعادة توليدها أو اختبار نسخة بديلة، دون إعادة إنشاء خطة الشهر كاملة.
